# 协议与实现范围

这是窄范围的 AIRMX PRO 兼容服务，不是通用 MQTT broker，也不是完整厂商云。协议依据来自社区 openairmx 代码与单户实测；完整归属见仓库 THIRD_PARTY.md。

## 已观察的通信

- HTTP 时间、genId 与 online 声明；已有配网设备也会重试连接旧云。
- 明文 MQTT 3.1/3.1.1；设备 ID 派生订阅/发布主题。
- 风机状态 `cmdId=210`，控制 `cmdId=100`；状态请求 `cmdId=40`。
- 常见模式编号：0 手动、1 原生 AI、2 静音、3 强力。其他固件必须以自己的状态和行为确认。

对已知主题格式，风机控制 `airmx/01/1/1/0/1/{deviceId}`，风机状态通常为 `airmx/01/0/1/1/1/{deviceId}`，检测仪数据 `airmx/01/1/0/1/1/{deviceId}`。服务只允许代码列出的设备来源、主题和匹配订阅，不接受任意主题代理。

## 签名与身份

在这个协议版本，签名为 MD5：去掉 sig 字段及 JSON 最外层括号的原始序列化内容，再接 `,` 与 deviceKey。字段顺序、空格、字符串转义均可能影响结果；不能随意解析再重新排序后称为等价。实现和公开测试向量见 recovery_server.py 与离线测试。

CONNECT 的密码只被当作候选，只有有效风机状态验签成功后才存为 key。注册数据目录 0700、文件 0600，校验属主、常规文件/目录和 symlink；写盘失败不抹掉旧 key。不能把任何 MQTT 密码都当成签名 key。

本地 HTTP genId 可将已配置风机 MAC 声明的 key 写入受保护存储；这属于未验签的登记声明，registered=true 不足以证明该 key 有效。无论来源如何，开放控制前仍需收到有效签名状态。MAC 不反转字节；设备 ID 不凭空套用他人的值。

## 控制与 API

受限 API 提供 `/api/status`、`/api/set-speed`、`/api/set-mode`。API 绑定明确 LAN IPv4，只接受配置的 HA 来源、正确 Host、Bearer token 且无浏览器 Origin。管理端只绑定 IPv4 回环。

控制要求风机在线、匹配命令订阅，以及最近约 360 秒内验签的状态；必要时请求刷新，无法取得则拒绝控制。风量 API 目前发送 power=1、mode=0 的手动指令，所以 HA 控制器在调速前必须核对实际电源，并在关机时暂停。不要将底层 set-speed 当成无副作用的旋钮。

## 数据含义

- `cadr` 是风量百分比，不是实测 m³/h。
- 以额定最大 550 m³/h 换算可作近似显示；具体型号需核对铭牌/参数，并明确“估算”。
- `prm` 看起来与转速相关，单位与标定未确认，不据此宣称实测换气量。
- `g4Percent`、`hepaPercent`、`carbonPercent` 在该固件表示已用百分比，不能标成剩余寿命。
- PM2.5 和 PM10 可能原始报文就是同值；不通过任意系数虚构 PM10。
- 检测仪约 300 秒一次网络上报是实测节奏，内部探头的采样频率未知。

HA API 的风机状态验签字段与检测仪 `signature_verified=false` 应分别理解。检测仪数据依靠精确来源/主题与网络边界限制，不声称它经过了与风机相同的密码验签。
